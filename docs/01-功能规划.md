# 01 功能规划 —— 功能模块与功能点

> mse-mp 功能总纲。配套文档：[02-权限规划](02-权限规划.md)（每个功能点的权限码与菜单 id）、[03-角色规划](03-角色规划.md)（谁能用）。
> 标记说明：全部为**一期已落地**能力（功能以工程 [README](../README.md) 与实际代码为准）；「主要角色」见 [03-角色规划](03-角色规划.md) 的建议角色清单。

## 一、模块总览与核心业务闭环

| # | 模块 | 页面菜单（menu_id） | 一句话定位 |
| --- | --- | --- | --- |
| 1 | 公众号接入 | 公众号管理（432） | 多账号/多租户接入、凭据加密、连通性测试、Token 状态 |
| 2 | 微信回调核心链路 | （无页面，流水呈现在消息事件页 435） | 验签/解密/幂等/粉丝流转/自动回复的入站主链路 |
| 3 | 粉丝管理 | 粉丝管理（434） | 关注/取关/扫码事件自动建档，管理端只读 |
| 4 | 消息事件 | 消息事件（435） | 入站消息/事件流水与详情、被动回复核查 |
| 5 | 自动回复规则 | 回复规则（436） | 七类匹配规则、文本/图文回复、优先级与启停 |
| 6 | 自定义菜单 | 菜单配置（433） | 每号一份草稿、可视化/JSON 双模式、同步微信 |
| 7 | 仪表盘 | 仪表盘（431） | 统计卡片 + 入站趋势 + 最近消息流水 |
| 8 | access_token 管理 | （支撑能力，状态呈现在公众号管理页） | 内存缓存 + mp_token 双写、预刷新、并发串行化 |
| 9 | 开放能力 | （无页面，经 mse-open 对外） | 粉丝/消息只读查询自注册开放给第三方 |

**核心业务闭环**：

```
接入公众号（录入 AppID/AppSecret/Token/EncodingAESKey，AES-GCM 加密落库）
  → 微信公众平台「服务器配置」填回调 URL / Token / EncodingAESKey → 提交验证（GET echostr）
  → 「测试」实取 access_token 验证凭据 → Token 状态列「有效」
  → 粉丝关注 / 发消息（微信推送到 /mp/callback/{appId}）
      → 验签 → 按加密模式解密 → 幂等去重 → 粉丝状态流转 → 落库（5 秒窗口内应答）
      → 命中自动回复规则 → 被动回复（文本/图文）
  → 运营：仪表盘看趋势 → 消息事件查流水 → 粉丝管理查档案
  → 菜单配置：编辑草稿 → 同步到微信 → 用户点菜单 → click 事件 → 命中菜单回复规则
```

## 二、公众号接入（一期）

每个租户可接入多个公众号；AppID 全局唯一（回调路由要求），接入时跨租户查重。

| 功能点 | 说明 | 主要角色 |
| --- | --- | --- |
| 接入公众号 | 录入 AppID / AppSecret / Token / EncodingAESKey（与公众平台「设置与开发-基本配置-服务器配置」一致）、类型（订阅号/服务号）、是否认证、消息加密方式（明文 plain / 兼容 compatible / 安全 safe）、备注 | 公众号管理员 |
| 凭据加密与不回显 | AppSecret / Token / EncodingAESKey 以 AES-256-GCM 加密落库（密钥 `mse.mp.crypt-key`），接口不回显；编辑时留空 = 保持不变；AppID 录入后不可改 | 公众号管理员 |
| 接入配置回显 | 「接入配置」弹窗展示回调 URL（`https://<域名>/api/mp/callback/<AppID>`）与 Token / EncodingAESKey 明文，逐项一键复制，供填入公众平台 | 公众号管理员 |
| 连通性测试 | 「测试」按钮真实调用微信 access_token 接口验证凭据，成功/失败原因直接提示 | 公众号管理员 |
| Token 状态列 | 列表展示 access_token 有效期与最近失败原因（40125 密钥错误 / 48001 未认证无权限等），失败即定位 | 公众号管理员 |
| 启用/停用 | 停用账号不再处理其回调推送（仍保留历史数据） | 公众号管理员 |
| 删除 | 逻辑删除；同 AppID（含已删）不可重复接入 | 公众号管理员 |

## 三、微信回调核心链路（一期）

匿名接口（以微信签名而非登录态鉴权），网关白名单 `/mp/callback/**`；单实例承接任意多个号。

| 功能点 | 说明 | 主要角色 |
| --- | --- | --- |
| 接入验证（GET） | sha1 验签后原样返回 echostr——公众平台「服务器配置-提交验证」即走此通道 | （系统自动） |
| 消息/事件推送（POST） | 验签 → 按加密模式 AES-CBC 解密（PKCS7 块 32，校验 receiveid）→ 幂等去重 → 粉丝状态流转 → 自动回复规则匹配 → 落库 → 微信 5 秒窗口内应答 | （系统自动） |
| 幂等去重 | `dedup_key` 唯一索引（MD5 锚点）挡微信对同一推送最多 3 次重试；回复内容落库缓存，重试直接复用，不重复执行规则 | （系统自动） |
| 类型归一化 | 事件：subscribe / subscribe_scan（带参扫码）/ unsubscribe / click / view / scan / location；消息：text / image / voice（含语音识别）/ video / shortvideo / location / link；载荷 JSON（snake_case）+ 解密后明文报文双份落库 | （系统自动） |
| 容错应答 | 不可恢复错误一律应答 success，避免微信约 5 秒间隔重试放大流量 | （系统自动） |
| 加密回复 | 兼容/安全模式下被动回复加密包装；回复 FromUserName 使用入站 ToUserName（gh_ 原始 ID） | （系统自动） |
| 跨租户路由 | 按 AppID 定位账号（跨租户 `runIgnore` 查号）后，消息处理固定在该账号所属租户上下文（`runAs`）内完成 | （系统自动） |

## 四、粉丝管理（一期，只读）

| 功能点 | 说明 | 主要角色 |
| --- | --- | --- |
| 自动建档与状态流转 | 关注/取关/带参扫码事件自动维护：关注状态、关注/取关时间与场景（如 ADD_SCENE_QR_CODE）、昵称头像、性别地区、UnionID、最近活跃时间 | 客服专员 |
| 资料不全标记 | 未认证号拉不到粉丝资料时标记「资料不全」，管理端可见 | 客服专员 |
| 粉丝检索 | 按公众号、关注状态（关注中/已取关）、关键词（OpenID / 昵称 / UnionID）筛选 | 客服专员 |

## 五、消息事件（一期，只读）

| 功能点 | 说明 | 主要角色 |
| --- | --- | --- |
| 消息/事件流水 | 按公众号、类别（事件/消息）、类型（subscribe/click/text/…）、关键词（OpenID / 内容 / 回复）检索入站流水 | 客服专员 |
| 消息详情 | 详情抽屉展示时间、公众号、OpenID、方向/类别/类型、MsgId、traceId、幂等键、归一化载荷、明文报文、被动回复缓存——排查「为什么回了/没回」的唯一入口 | 客服专员 |
| 已回复标识 | 列表「已回复」列与回复缓存一致，命中规则的消息可核对回复内容 | 客服专员 |

## 六、自动回复规则（一期）

| 功能点 | 说明 | 主要角色 |
| --- | --- | --- |
| 七类匹配类型 | 关注（subscribe）/ 取关（unsubscribe）/ 菜单点击（Key 精确）/ 任意消息（msg_any）/ 关键词精确（keyword_exact）/ 关键词包含（keyword_contains，多关键词 `,` 空格 `\|` 分隔）/ 兜底（default） | 内容运营 |
| 匹配顺序 | 固定：subscribe → unsubscribe → click → msg_any → keyword_exact → keyword_contains → default；同类型内 priority 大者先 | 内容运营 |
| 回复类型 | 文本 / 图文（≤8 条，标题必填，含摘要/封面/原文链接） | 内容运营 |
| 启停与优先级 | 规则可独立启停；优先级数值大者先命中 | 内容运营 |
| 菜单 Key 联动 | 「菜单点击」类型的 Key 下拉与菜单草稿、既有规则的 Key 联动（可选可输） | 内容运营 |

## 七、自定义菜单（一期）

| 功能点 | 说明 | 主要角色 |
| --- | --- | --- |
| 草稿管理 | 每号一份草稿（与微信 `menu/create` 同构 JSON），保存草稿 ≠ 发布；草稿状态（有改动/已同步）可见 | 内容运营 |
| 可视化 / JSON 双模式 | 可视化模式拖拽式增删改排序（一级 ≤3、二级 ≤5，名称 ≤30 字）；JSON 模式直接编辑同构 JSON，高级用法与批量调整走 JSON | 内容运营 |
| 菜单类型 | click / view / miniprogram / media_id / view_limited / article_id / article_view_limited / scancode_push / scancode_waitmsg / pic_sysphoto 等微信全量类型；小程序类型可选本租户已接入的小程序 AppID | 内容运营 |
| 同步到微信 | 草稿提交微信生效（手机端即时可见）；未认证号返回 48001 时附「公众号未认证，无自定义菜单权限」友好提示 | 内容运营 |
| 拉取线上 / 删除线上 | 拉取线上菜单（归一化，兼容 JSON/XML 两种返回，与草稿比对）；删除线上菜单（本地草稿保留） | 内容运营 |

## 八、仪表盘（一期）

| 功能点 | 说明 | 主要角色 |
| --- | --- | --- |
| 统计卡片 | 接入公众号数 / 关注粉丝数 / 今日消息事件数 / 启用中规则数 | 公众号管理员 |
| 入站趋势 | 近 7 天入站事件/消息双线趋势（后端支持 ≤30 天，Java 侧分桶，三方言数据库通用） | 公众号管理员 |
| 最近消息流水 | 最近 10 条消息/事件（时间/公众号/OpenID/类型/内容摘要） | 公众号管理员 |

## 九、access_token 管理（支撑能力）

| 功能点 | 说明 | 主要角色 |
| --- | --- | --- |
| 缓存与双写 | 每号一份内存缓存 + `mp_token` 表双写；过期前 5 分钟预刷新，未到期直接用缓存 | （系统自动） |
| 并发串行化 | 同 AppID 并发刷新用对象锁串行化（等价 singleflight），避免同时打满微信配额 | （系统自动） |
| 失败落库 | 成功/失败均落库——失败原因（40125 密钥错误 / 48001 能力未开放等）供公众号管理页 Token 状态列展示与排查 | （系统自动） |
| 凭据变更联动 | 账号凭据变更后自动清空该号缓存，下次使用即以新凭据刷新 | （系统自动） |

## 十、开放能力（一期，经 mse-open 自注册）

遵循仓库「能力开放接入标准」：业务自注册、mse-open 统一窗口、业务新增开放能力零改动 mse-open。

| 功能点 | 说明 | 主要角色 |
| --- | --- | --- |
| 粉丝只读查询开放 | `mp-api` 契约 `RemoteMpFanService.pageFans` → 对外路径 `GET /open/api/mp/fans`（开放码 `open:mp:fans-page`）；租户经上下文隐式透传 | 公众号管理员（授权配合） |
| 消息只读查询开放 | `mp-api` 契约 `RemoteMpMessageService.pageMessages` → 对外路径 `GET /open/api/mp/messages`（开放码 `open:mp:messages-page`） | 公众号管理员（授权配合） |
| 目录自注册 | `MpOpenApiContributor` 声明清单，应用就绪后自动推送 mse-open 目录（幂等 upsert + 周期重推自愈），管理端「API 目录」可启停 | 公众号管理员 |

「主动发消息」属微信侧重能力（见第十一节边界），开放通道暂不提供。

## 十一、已知边界与后续演进（规划，勿当已有能力交付）

以下能力一期**未实现**（go-wechat 同样未实现，按需扩展）：

| 能力 | 说明 |
| --- | --- |
| 客服消息 / 模板消息 | 主动触达用户的两条通道，未实现 |
| 素材上传 / 图文群发 | 素材库与群发能力未实现；群发等「主动发消息」依赖 `mp_message.direction=out`（字段已预留） |
| 粉丝标签管理 / 带参二维码生成 | 标签与二维码生成接口未实现（带参扫码的**事件接收**已支持，subscribe_scene 记录） |
| JSSDK 签名 / 网页授权 OAuth / 微信支付 | 均未实现 |

其他演进事项：独立库租户形态（粉丝/消息路由租户库，按 mse-demo `@GlobalTransactional` 模式处理）；达梦/金仓建表脚本暂未随 jar 提供（一期以 MySQL 为主验证）。
