# 03 客服专员操作手册

> 建议角色：`mp_service`｜数据范围：本租户全部｜菜单：粉丝管理、消息事件（只读），回复规则（只读对照）。
> 定位：用户互动的第一响应人——负责**核查消息进出**（谁发了什么、系统回了什么）、**查询粉丝档案**（关注状态、来源）、**跟进回复命中情况**。粉丝与消息由回调链路自动维护，本岗位为纯只读视角，不直接回复用户（被动回复内容由内容运营在「回复规则」统一维护）。

## 一、职责与页面清单

| 职责 | 页面 |
| --- | --- |
| 核查用户消息是否进来、命中了哪条规则、回复了什么 | 消息事件 |
| 查询粉丝关注状态/来源/活跃情况 | 粉丝管理 |
| 对照回复规则，判断「为什么回了/没回」 | 回复规则（只读） |
| 看当日消息量与趋势 | 仪表盘（只读） |

## 二、消息事件核查（核心操作）

> 路径：微信公众号 → **消息事件**。

### 2.1 找一条消息

筛选条件自上而下组合：

1. 「公众号」下拉先锁定号（不选即全部）；
2. 「类别」：**事件**（关注/取关/点菜单/扫码等）或**消息**（文字/图片/语音等）；
3. 「类型」：精确到 subscribe、click、text、image 等（下拉可搜索）；
4. 关键词框：输入 **OpenID / 内容 / 回复** 片段，回车查询。

列表列：时间、公众号、OpenID、类别、类型、内容摘要、**已回复**（是/否）、操作「详情」。

### 2.2 看懂「消息详情」

点「详情」打开抽屉，排查「为什么回了/没回」就看这里：

| 字段 | 用途 |
| --- | --- |
| 时间 / 公众号 / OpenID | 定位是哪个粉丝、哪个号、什么时候 |
| 方向 / 类别 / 类型 | in 收到的什么事件或消息（out 为系统预留的发送方向，一期不会有） |
| MsgId / traceId | 微信消息号与链路追踪号——反馈给技术排查时报这两个号 |
| 幂等键 | 同一条推送的唯一锚点：同键只会有一条记录，微信重试不会产生重复 |
| 载荷 | 归一化后的报文内容（文本消息看 content，语音消息含语音识别结果） |
| 明文报文 | 解密后的原始报文，核对细节用 |
| 回复 | 系统被动回复的内容缓存——与用户微信里实际收到的回复一致 |

### 2.3 常见核查结论

| 详情页看到 | 结论 |
| --- | --- |
| 「已回复=是」，回复内容正常 | 链路正常，用户已收到（可让用户重进会话查看） |
| 「已回复=否」 | 没有命中任何启用中的规则——去「回复规则」对照匹配类型/匹配值，转内容运营补规则 |
| 记录不存在 | 消息根本没进来：先查该号 Token 状态（公众号管理页）与公众平台服务器配置是否被停用，转公众号管理员 |

## 三、粉丝档案查询

> 路径：微信公众号 → **粉丝管理**。

- 筛选：公众号、关注状态（关注中 / 已取关）、关键词（**OpenID / 昵称 / UnionID**）。
- 列表列：粉丝（头像+昵称）、OpenID、关注状态、性别、地区、**关注场景**、关注时间、取关时间、最近活跃。
- 读法：

| 想知道 | 看哪里 |
| --- | --- |
| 这位粉丝还在关注吗 | 关注状态列（已取关的会显示取关时间） |
| 他从哪来 | 关注场景列（如 ADD_SCENE_QR_CODE = 扫二维码关注） |
| 最近有没有互动 | 最近活跃列 |
| 资料是空的 | 「资料不全」属正常边界：未认证公众号拉不到粉丝昵称头像等资料，认证后新粉丝会带全 |

> 粉丝档案由关注/取关/扫码事件自动维护，**无法手工新增或修改**——页面没有编辑按钮属正常设计。

## 四、与规则对照（只读）

「回复规则」页对你只读开放，用途：

1. 用户投诉「没回复」时，核对是否存在**启用中**且能命中该消息的规则（匹配类型、匹配值逐字比对）；
2. 用户问「你们自动回复都有些什么」时，按号浏览规则清单作答；
3. 发现规则缺口（高频消息无规则覆盖）——记录需求转内容运营，**不要**催促或自行改动（本角色无编辑权限）。

## 五、客服注意事项

1. **本岗位不直接回消息**：一期无客服对话工作台，对用户的应答全部经「自动回复规则」实现；个性化诉求（如退款）请在微信侧以其他渠道（如留下的人工联系方式）承接。
2. **别把 OpenID 当微信号**：OpenID 是用户在该公众号下的编号，只用于检索定位，不能用它加好友。
3. **语音消息**：详情「载荷」里的识别文字是微信语音转文本结果，可直接读，不必听语音。
4. **一条消息只会有一条记录**：看到微信端用户说"发了好几遍"而系统只有一条，是幂等去重生效（微信重试被挡），非数据丢失。
5. **跨号数据**：顶部「公众号」下拉不选即查本租户全部号——注意别把 A 号的粉丝情况当成 B 号的答复口径。
